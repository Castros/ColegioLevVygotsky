🔍 Strapi Webhook Debugger

Step 1: Use webhook.site to capture Strapi webhook

1. Go to https://webhook.site

2. Copy your unique URL (it will look like: https://webhook.site/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx)

3. In Strapi, go to Settings → Webhooks

4. Edit your webhook or create a new test webhook

5. Use the webhook.site URL as the webhook URL

6. Trigger the webhook from Strapi (update content or click "Trigger" button)

7. Go back to webhook.site to see what data Strapi sent

What to check in webhook.site:

  • HTTP Method: Should be POST
  • Headers: Check if your Authorization header is present
  • Body: See what JSON structure Strapi is sending

⚠️ Common Issues with Strapi v3:

  • Custom body not supported: Strapi v3 may not let you customize the JSON body. It sends its default payload structure.
  • GitHub expects specific format: GitHub repository_dispatch requires {"event_type": "..."} in the body.
  • Strapi sends different format: Strapi typically sends {"event": "entry.create", "model": "homepage", "entry": {...}}

Solution Options:

Option A: Use webhook relay (Lambda or similar)

Have Strapi call a middleware service that translates the webhook format before calling GitHub.

Option B: Modify GitHub workflow to accept Strapi's format

Change the workflow trigger to accept any POST request, not just repository_dispatch.

Option C: Manual trigger

Use GitHub's workflow_dispatch (manual trigger) when you want to rebuild.

Quick Test: Manual GitHub Actions Trigger

To verify GitHub Actions works independently:

  1. Go to: Your GitHub Actions page
  2. Click on "Build and Deploy to S3" workflow
  3. Click "Run workflow" dropdown
  4. Click green "Run workflow" button

If this works, the issue is purely with the webhook trigger, not the build process.
